# Spec-Driven Development (SDD) Workflow

## Філософія SDD
SDD переводить роботу з агентами з режиму «виконай цей список дій» у режим **«досягни цієї вимірної мети за фіксованими правилами»**.

## Фази SDD-циклу:

1. **Propose (Специфікація):**
   - Формулюється чітка мета (Objective) та детерміновані критерії успіху (Measurable Acceptance Criteria).
   - Фіксуються Non-Goals (що агенту суворо заборонено робити або змінювати).
   - Встановлюється бюджет токенів та ітерацій.
2. **Approve (Схвалення):**
   - Користувач перевіряє специфікацію, узгоджує архитектурні рішення та знімає відкриті питання (Open Questions).
3. **Apply (Автономне виконання):**
   - Агент ітерує в закритому циклі: *План → Дія → Тест → Автокорекція*.
   - Дії обмежені виділеним скоупом файлів та бюджетом токенів.
4. **Verify (Детерміновані Quality Gates):**
   - Перевірка типів, тестів, лінту, бандлу та UI-вимог.
5. **Archive (Фіксація та журналювання):**
   - Підготовка Walkthrough, фіксація обґрунтування рішень (Decision Rationale) та очищення тимчасових артефактів.
