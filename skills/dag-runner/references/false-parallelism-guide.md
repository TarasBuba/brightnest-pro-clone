# False Parallelism Guide: Запобігання конфліктам у паралельних субагентах

## Що таке False Parallelism?
**False Parallelism** (хибний паралелізм) виникає, коли два субагенти одночасно намагаються модифікувати:
1. Той самий файл реалізації або файл тестів.
2. Спільний індексний файл/бочку (`index.ts`, `mod.rs`, `__init__.py`).
3. Спільну схему бази даних, міграцію або конфігурацію роутера.
4. Спільний маніфест залежностей (`package.json`, `Cargo.toml`).

## Правила декомпозиції (Anti-Conflict Matrix):

1. **Pre-wave Extraction (Wave 0):**
   - Усі спільні типи, інтерфейси, DTO та точки входу створюються **до** запуску паралельних воркерів у послідовній Wave 0.
2. **Exclusive File Ownership:**
   - Кожен паралельний субагент отримує список директорій/файлів із забороною торкатися файлів за межами свого скоупу:
     - Worker A: `src/features/auth/**`
     - Worker B: `src/features/billing/**`
3. **Post-wave Aggregator (Integration Wave):**
   - Реєстрація модулів у головному роутері чи `index.ts` виконується єдиним субагентом-інтегратором після злиття гілок.
