# Model Routing & Token Budgeting Guide

## 1. Принципи маршрутизації моделей (Model Routing)

Для забезпечення максимальної швидкості та мінімізації витрат використовується дворівнева або трирівнева маршрутизація:

| Модель | Рекомендоване призначення | Коли обирати |
| :--- | :--- | :--- |
| **`flash_lite` / `flash`** | Механічна кодогенерація, шаблонні юніт-тести, конвертація даних, простий пошук, парсинг файлів. | Вузько окреслені задачі з чіткою специфікацією, де не потрібні складні архітектурні рішення. |
| **`inherit` (default)** | Стандартна розробка фіч, інтеграційні задачі середньої складності, локальні рефакторинги. | Задачі із середнім рівнем контексту та стандартними вимогами. |
| **`pro`** | Архітектурна декомпозиція, проектування спільних контрактів/типів, аналіз складного legacy коду, **Red-Team Verifier**, аудит безпеки та багатомодульна інтеграція. | Задачі з високою ціною помилки (blast radius), де потрібні глибоке міркування та знаходження нетривіальних крайових випадків. |

## 2. Бюджети токенів та ітерацій (Token & Iteration Budgets)

1. **Iteration Cap:**
   - На будь-яку атомарну підзадачу субагента встановлюється жорсткий ліміт: максимум **3-5 кроків** викликів інструментів або 2 цикли автовиправлення тестів.
2. **Token Ceiling:**
   - Кожна хвиля має встановлений ліміт токенів (наприклад, 30k–50k токенів на воркера).
3. **Escalation Trigger:**
   - Якщо субагент витрачає понад 80% бюджету без проходження Quality Gate — зупинка виконання та генерація статусного репорту.
