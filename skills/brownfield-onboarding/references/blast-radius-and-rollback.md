# Blast Radius Assessment & Rollback Protocol

## 1. Розрахунок Blast Radius (Меж впливу)

Перед зміною файлу або компонента дай відповіді на три запитання:

1. **Хто імпортує цей модуль?**
   - Виконай ripgrep/grep пошук за назвою функції/типу/файлу по всьому репозиторію.
2. **Чи змінюється публічний інтерфейс/контракт?**
   - Якщо додається/змінюється обов'язковий аргумент функції або тип у TypeScript — радіус впливу є глобальним для всіх клієнтів цієї функції.
3. **Чи зачіпаються спільні дані або сайд-ефекти?**
   - Чи змінюється глобальний стан, схема БД, localStorage, HTTP заголовки або формат відповідей API?

---

## 2. Матриця рівнів Blast Radius:

- **Low Blast Radius:** Ізольований внутрішній хелпер або компонент, що використовується лише в 1 місці та покритий модульними тестами.
- **Medium Blast Radius:** Спільний UI-компонент, кастомний хук або сервіс, що використовується в кількох модулях.
- **High / Critical Blast Radius:** Глобальні типи, схема бази даних, middleware автентифікації, головний роутер або білд-конфігурація.

---

## 3. Протокол швидкого Rollback:

1. **Для роботи в гілці:**
   ```bash
   git checkout main
   git branch -D feature/sandbox-experiment
   ```
2. **Для локальних незакомічених змін:**
   ```bash
   git restore .
   git clean -fd
   ```
3. **Для змін після коміту:**
   ```bash
   git revert --no-edit <commit-hash>
   ```
